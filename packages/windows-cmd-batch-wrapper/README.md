# Windows CMD/BAT Wrapper

Status: supported experimental transport wrapper.

This package provides a thin Windows `.cmd` CLI over the Go `canonicalfs` daemon HTTPS API.

Use it when CMD/BAT automation needs to call CanonicalFS through the Go daemon. It does not perform local filesystem security checks and is not an independent filesystem security boundary. Security-sensitive filesystem operations must still be authorized and executed by the Go daemon.

## Requirements

- `cmd.exe`
- PowerShell 7 (`pwsh.exe`), normally at `%ProgramFiles%\PowerShell\7\pwsh.exe`
- A running `canonicalfs-daemon`
- The sibling `packages/powershell/CanonicalPath/DaemonClient.cs` transport source; preserve this directory layout when installing the wrapper.

The launcher uses that full PowerShell 7 path and never probes or falls back to Windows PowerShell 5.1. For another trusted PowerShell 7 installation, set `CANONICALPATH_POWERSHELL` to the full executable path. The local Node check runners use the same setting and verify the actual PowerShell major version and Core edition; a missing or unusable configured runtime fails instead of silently skipping the Windows check.

## Usage

Have the trusted launcher load the current private bootstrap. For example,
inside a PowerShell 7 session:

```powershell
$bootstrapDirectory = 'C:\Users\Alice\AppData\Local\CanonicalFS\launch-001'
$connection = Get-Content -LiteralPath (Join-Path $bootstrapDirectory 'connection.json') -Raw | ConvertFrom-Json
$env:CANONICALFS_DAEMON_URL = $connection.endpoint
$env:CANONICALFS_DAEMON_TOKEN = $connection.token
$env:CANONICALFS_TLS_CERTIFICATE_SHA256 = $connection.certificate_sha256
$env:CANONICALFS_TLS_CA_FILE = Join-Path $bootstrapDirectory 'ca.pem'
# A child CMD process inherits these settings; the request path is fixed.
cmd.exe /d /c 'packages\windows-cmd-batch-wrapper\canonicalfs.cmd < request.json'
```

Create the UTF-8 JSON request file first (for example, `request.json` containing
`{"op":"health"}`). A CMD session with the same trusted environment can redirect
the file directly:

```cmd
packages\windows-cmd-batch-wrapper\canonicalfs.cmd < request.json
```

HTTPS is required on every endpoint, including loopback.
`CANONICALFS_TLS_CERTIFICATE_SHA256` is mandatory and contains the leaf
certificate DER SHA-256 as 64 hexadecimal characters. The optional
`CANONICALFS_TLS_CA_FILE` supplies a trusted CA PEM; it is required for the
private CA generated by `canonicalfs-bootstrap`. Without it, the client uses
platform CA trust plus the mandatory pin. Hostname, validity and chain checks
remain active. The Bash/curl `public_key_pin` value is a different format and
must not be placed in `CANONICALFS_TLS_CERTIFICATE_SHA256`.

The bootstrap directory must come from the trusted launcher, with private
access under a trusted OS filesystem/volume root. Do not obtain a CA or expected
pin from the endpoint being authenticated. Generate a new bootstrap directory
for each daemon launch, update the environment for that instance, and keep
`connection.json`/`token` private. Generated certificates expire after 24 hours.
See the [release/process guide](../../docs/release-process.md) for provisioning
and daemon TLS flags. Plain HTTP, missing pins and incorrect certificate
identities fail without a fallback.

The wrapper accepts at most 1 MiB of UTF-8 JSON. Generate files with a JSON serializer; request values must never be assembled into a CMD command, `CALL`, `SET`, or `echo` expression. Positional arguments are no longer processed as of `2026.10.10-1`.

| Operation | JSON request fields |
| --- | --- |
| `health`, `caps` | `op` |
| `open-project` | `op`, `project_id`, `host_root` |
| `close-project` | `op`, `project_id` |
| `mkdir-all`, `remove`, `stat` | `op`, `project_id`, `path` |
| `rename` | `op`, `project_id`, `path`, `target` |
| `read-text` | `op`, `project_id`, `path`, optional `max_bytes` |
| `write-text` | `op`, `project_id`, `path`, `text` |

For example:

```json
{"op":"write-text","project_id":"my-project","path":"safe/file.txt","text":"hello from cmd"}
```

`canonicalpath.cmd` accepts the same JSON stdin interface. Both shims call the same fixed `canonicalfs.ps1` script. PowerShell callers can invoke that script directly with named parameters and variables:

```powershell
& ./packages/windows-cmd-batch-wrapper/canonicalfs.ps1 -Operation write-text -ProjectId my-project -Path safe/file.txt -Text $text
```

The Bash wrapper has a separate breaking change: its `write-text` command now
accepts the text on stdin and rejects a third positional text argument. The CMD
wrapper continues to receive the `text` field inside its JSON stdin request.

Requests have a non-resettable 30-second total deadline covering connection, upload, headers and the entire body, reject redirects, and bound decoded responses to 24 MiB. `CANONICALFS_TIMEOUT_MILLISECONDS` and `CANONICALFS_MAX_RESPONSE_BYTES` can lower these limits. Both JSON stdin and named parameters enforce the 1 MiB serialized request ceiling before base64 allocation. The bearer token is read from the environment and never forwarded in process arguments.

```bash
pnpm cmd:smoke

```
