# CanonicalPath PowerShell Module

Experimental lexical CanonicalPath module with typed CanonicalFS daemon HTTPS client helpers. The current daemon workflow and local checks use PowerShell 7 Core; Windows PowerShell 5.1 remains a legacy compatibility declaration.

Use this module when PowerShell automation needs to share CanonicalPath identity or call the Go daemon. The split is the same as the rest of the repository: PowerShell can validate/serialize or transport a path, but the Go daemon owns security-sensitive filesystem I/O.

The lexical helpers only implement deterministic path identity and serialization. The CanonicalFS functions are JSON HTTPS client wrappers for the Go daemon. This module does not implement local filesystem security; security-sensitive filesystem I/O must stay delegated to the Go CanonicalFS daemon.

## Daemon Client

```powershell
Import-Module ./packages/powershell/CanonicalPath/CanonicalPath.psd1
# This directory was provisioned by the trusted launcher for this daemon instance.
$bootstrapDirectory = 'C:\Users\Alice\AppData\Local\CanonicalFS\launch-001'
$connection = Get-Content -LiteralPath (Join-Path $bootstrapDirectory 'connection.json') -Raw | ConvertFrom-Json
$Client = New-CanonicalFSDaemonClient -Endpoint $connection.endpoint -Token $connection.token `
    -CertificateSha256 $connection.certificate_sha256 `
    -CACertificatePath (Join-Path $bootstrapDirectory 'ca.pem')
Get-CanonicalFSDaemonHealth -Client $Client
Get-CanonicalFSDaemonCapabilities -Client $Client
Open-CanonicalFSProject -Client $Client -ProjectId 'project-1' -HostRoot 'C:\Users\Alice\Repo'
Read-CanonicalFSText -Client $Client -ProjectId 'project-1' -Path 'README.md' -MaxBytes 1048576
```

HTTPS is required even on loopback. Every client requires a trusted SHA-256
fingerprint of the leaf certificate DER: exactly 64 hexadecimal characters.
`-CertificateSha256` defaults to `CANONICALFS_TLS_CERTIFICATE_SHA256`;
`-CACertificatePath` defaults to `CANONICALFS_TLS_CA_FILE`. A CA file is needed for
the private CA generated by `canonicalfs-bootstrap`. When it is omitted, normal
platform CA trust still applies alongside the required pin. Hostname, certificate
validity and chain validation remain enabled. A missing pin, HTTP endpoint or
incorrect server identity fails; there is no plaintext or unverified fallback.

Trust material must come from a protected local bootstrap or the trusted
launching application, never from the endpoint being authenticated. The Go
`canonicalfs-bootstrap` command creates a new private directory containing
`connection.json`, `ca.pem`, `certificate.pem`, `key.pem` and `token`. Its parent
must already be private, and the OS filesystem/volume root must be trusted.
Generate a new directory for each daemon launch and update clients together:
the token, CA, certificate and pin rotate, and generated certificates expire
after 24 hours. See the repository [release/process guide](../../../docs/release-process.md)
for daemon startup and bootstrap provisioning. `connection.json` contains a
capability token and must remain private.

PowerShell uses `certificate_sha256`; Bash/curl uses the different
`public_key_pin` field. Do not interchange these two pin formats.

Supported daemon operations are health, capabilities, project open/close, read/write file or UTF-8 text, stat, mkdirAll, remove, and rename. All non-health calls send `Authorization: Bearer <token>`.

PowerShell text writes use `Write-CanonicalFSText -Text $text`. When calling the
shell wrappers, use their specific input contract: Bash `write-text` accepts
only project/path arguments and reads text from stdin; CMD reads a JSON stdin
request containing a `text` field. Bash's former positional text argument is
rejected.

Clients must be created with `New-CanonicalFSDaemonClient`. The sealed client keeps the bearer private; ordinary display, JSON and CLIXML serialization omit it. Public `Token` properties and arbitrary client property bags are no longer supported. Serialization produces diagnostics, not a credential-bearing client that can be restored for requests.

Every response, including errors, is counted after gzip/deflate decoding before JSON parsing. The local hard ceilings are 24 MiB and a 30-second overall network deadline. `-MaxResponseBytes` and `-TimeoutMilliseconds` can lower those limits, but cannot raise or disable them. Redirects are rejected.

## Test

```powershell
# Run from the repository root in PowerShell 7.
pwsh -NoProfile -File ./packages/powershell/CanonicalPath/test/CanonicalPath.Tests.ps1 -RepoRoot .
pwsh -NoProfile -File ./packages/powershell/CanonicalPath/test/CanonicalFSDaemonClient.Smoke.ps1 -RepoRoot .
```

From the repository root, `pnpm ps:test` runs the local smoke suite with PowerShell 7. Windows defaults to the full `%ProgramFiles%\PowerShell\7\pwsh.exe` path; other platforms use `pwsh`. Set `CANONICALPATH_POWERSHELL` to a trusted PowerShell 7 executable for a different installation. The selector verifies major version 7 or later and the Core edition. An unavailable default on non-Windows platforms is reported as a skip; a missing Windows runtime or an invalid explicit selection is an error. There is no automatic Windows PowerShell fallback or probe. `--all-available` now retains this PowerShell 7-only policy.

`pnpm ps:alloc` runs a bounded private-bytes smoke check for repeated lexical helper loops and daemon client object construction, using the same PowerShell 7 selector.

`pnpm ps:transport:alloc` starts the Go daemon with a temporary allowlisted root and runs a bounded private-bytes smoke check over repeated live daemon HTTPS calls, using the same PowerShell 7 selector.

The repository retains legacy Windows PowerShell 5.1 compatibility metadata and
an explicit hosted CI choice. Standalone daemon startup in this smoke requires
PowerShell 7 Core; the legacy CI lane supplies an external TLS daemon. Local
commands, daemon security tests and the CMD wrapper do not probe or fall back
to Windows PowerShell.

The vector tests consume shared JSON vectors from `spec/testdata/*_cases.json`.
When run independently, the daemon smoke creates a protected temporary parent,
generates per-launch credentials with `canonicalfs-bootstrap`, and starts the
daemon with certificate/key files and a private `-token-file`. It removes the
fixture after stopping the daemon. Root runners can instead supply `-Endpoint`,
`-Token` and `-HostRoot` with trusted CA/certificate-pin environment settings;
that mode does not create or reconfigure a daemon. Filesystem security-sensitive
I/O remains enforced by Go.
